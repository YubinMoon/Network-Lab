# AGENTS.md — Coding Agent Instructions

## Mission

Implement a browser-only IPv4 Layer 2 / Layer 3 network visualization lab.

The application must let users build a topology with `Host`, `Switch`, `Router`, and `Link` objects, then send packets and inspect the exact processing path through Ethernet, ARP, switching, IPv4 routing, TTL, and ICMP.

## Non-negotiable scope

Implement:

- IPv4 only.
- Ethernet-like Layer 2 frame forwarding.
- ARP request/reply and ARP cache.
- Switch MAC learning.
- Broadcast flooding.
- Unknown unicast flooding.
- Known unicast forwarding.
- IPv4 datagram forwarding.
- Routing table lookup.
- Longest Prefix Match.
- TTL decrement and TTL-expired drop.
- ICMP Echo Request / Echo Reply.
- Generic IPv4 packet with RAW payload.
- Auto network segment detection.
- Auto IP address assignment.
- Auto default gateway assignment.
- Connected route generation.
- Auto-generated static route generation.
- Animated packet movement on links.
- Event log, packet detail, layer view, and binary prefix match view.

Do not implement:

- IPv6.
- TCP.
- UDP.
- DHCP.
- DNS.
- NAT.
- VLAN.
- STP.
- Wireless.
- Dynamic routing protocols such as RIP, OSPF, IS-IS, or BGP.
- Real physical layer behavior.
- Server-side persistence.
- Professor assignment or grading features.

## Accuracy policy

Favor correctness and inspectability over visual simplicity.

Every non-trivial packet decision must be explainable through:

1. Animation.
2. Event log.
3. Packet detail panel.
4. Relevant table highlight.
5. Drop reason if the packet fails.

## Routing policy

Routing is static.

`Auto Static` routes are generated by the application to reduce user configuration burden. They must not be presented as RIP, OSPF, or any other routing protocol.

Route type precedence for identical destination/prefix entries:

1. `Connected`
2. `Manual Static`
3. `Auto Static`
4. `Default`

Longest Prefix Match is always the primary route selection rule. Type precedence only resolves equal prefix length conflicts.

## Network segment policy

A `Network Segment` represents one Layer 2 broadcast domain and one IPv4 subnet configuration unit.

- Switches extend a segment.
- Routers separate segments.
- Hosts do not forward frames.
- ARP operates only inside one segment.
- Direct router-to-router links should be treated as point-to-point segments.

Default addressing policy:

- LAN segment: `10.0.N.0/24`
- Router-to-router point-to-point segment: `10.255.N.0/30`
- First router interface in LAN: host offset `.1`
- Additional router interfaces in LAN: `.2`, `.3`, ...
- Host interfaces in LAN: `.10`, `.11`, `.12`, ...

## L2 loop policy

VLAN and STP are out of scope.

If a topology creates an unsupported Layer 2 switching loop, block packet simulation and show:

```text
Unsupported L2 Loop Detected
This topology creates a Layer 2 loop. STP is not supported in this lab.
```

## Code quality requirements

- Use TypeScript strict mode.
- Keep domain logic separate from React components.
- Put IP math, route lookup, segment detection, ARP, and simulation logic in pure functions where possible.
- Write unit tests for pure domain logic.
- Keep animation state separate from persistent topology state.
- Avoid embedding networking logic inside React components.
- Prefer deterministic simulation events for testability.

## TODO and Git workflow

- Maintain `docs/TODO.md` as the source of truth for planned work, in-progress work, and completed work.
- Review `docs/TODO.md` before starting a task and update it when task status changes.
- Keep task entries small enough to verify with a concrete check.
- After completing a work unit, update `docs/TODO.md` and commit the completed work.

## Recommended stack

- Vite + React + TypeScript.
- `@xyflow/react` for canvas/node graph editing.
- `zustand` for global state.
- `lz-string` for URL-safe state compression.
- `vitest` for unit tests.

## First implementation target

The first working milestone should support this topology:

```text
Host A ─ Switch S1 ─ Router R1 ─ Switch S2 ─ Host B
```

Expected behavior:

1. Auto-detect two LAN segments.
2. Auto-assign IP addresses.
3. Auto-assign default gateways.
4. Generate connected routes.
5. Generate auto static routes if needed.
6. Send ICMP Echo Request from Host A to Host B.
7. Show ARP for Host A to gateway.
8. Show switch MAC learning.
9. Show router decapsulation, TTL decrement, route lookup, and re-encapsulation.
10. Show ARP for Router R1 to Host B if needed.
11. Deliver ICMP Echo Request.
12. Generate and deliver ICMP Echo Reply.
